## 4. 五个坑（都是真实调试出来的）

### 4.1 不要用 IntersectionObserver 驱动入场

**现象**：用户从锚点直达、或浏览器恢复上次滚动位置时，落点上方已在视口内的元素
会永远卡在 `opacity:0`。

**做法**：`index.html` 里所有滚动驱动逻辑（`onScroll` / `tonePass` / `revealPass`）
都跑在**一个 rAF 轮询循环**里，比较 `scrollY` 是否变化。空闲时每帧只做一次数值比较，
元素显形后即从待办表移除。顺带解决 iOS 惯性滚动时 scroll 事件被节流的问题。

**别改回事件监听**。

### 4.2 固定左栏跨明暗交界时文字会消失

左栏是 `position:fixed` 的，上半截可能在深色图上、下半截已经进了浅色区。
整栏统一跟随 `body` 着色必然有一头看不见。

**做法**：`blockAt(y)` 查某个视口高度背后是哪个区块，左栏各块与顶栏各自
设 `data-lt="dark|light"` 取色。嵌板结构改造后这条**更关键**（左右两侧会一直漏出深色画面）。

### 4.3 `<img>` 必须有 `height:auto`

`<img width="1920" height="1080">`（防跳版用）在没有 `height:auto` 时会压过
CSS 宽度，把图拉变形。全局 img 规则里已加，别删。

### 4.4 降级模式不能吞内容

`prefers-reduced-motion` 下曾把整个开场面板 `opacity:0`，结果副题文案
「名校路径的新标准」彻底消失 —— 那句话只在面板里出现过。

**做法**：降级时给面板加 `.lean`，只收起与左栏重复的目录，**保留副题**。
新增任何"降级时隐藏 X"的规则前，先确认 X 的内容在别处还有。

### 4.5 黄铜色分深浅两个令牌

`--brass: #B8873F` 在深底上没问题，落到 `--paper: #D8D9CB` 上只有 **2.2:1**，不可读。
浅底一律用 `--brass-ink: #6B4B1A`（灰绿面 5.56:1，奶白面 7.39:1）。
但**卡片画面区是深底**，那里的序号要用 `--brass-lt`，别被 `.panel` 的规则带走。

### 4.6 半透明文字色要按合成后的结果算对比度

`--on-light-muted` 原本是 `rgba(22,24,26,.60)`。按 alpha 合成到实际底色上再算：
灰绿面 **4.11:1**、奶白面 4.55:1、`--paper-2` 4.28:1 —— 灰绿面不过 AA。
（样板阶段记的"对比度 AA 零缺陷"是错的：大概只比了不透明令牌对，
没把 alpha 合成算进去。）

实算最低要 `.64`，现已改成 **`.68`**（灰绿 5.2:1 / 奶白 6.0:1），
与正文 12.5:1 的层级差还在。**新增半透明文字色一律先合成再算，
而且要拿两种嵌板表面里更暗的那个（灰绿 #D8D9CB）当基准。**

### 4.7 左栏可读性靠出图流水线保证，不要在 CSS 里贴垫片

嵌板结构要求画面最左那条留亮（4.6 上面那节 + `PLAN-v4.md` A 批复盘第 2 条），
但固定左栏那些 9–15px 浅色小字正好压在这条上。B 批实测：11 个滚动位置里
有 6 个掉到 **2.3–4.3:1**，最差的是第四章那张（翻转后左边是浅色大理石柱）。

**试过在每个左栏文字块底下垫一片软边暗底 —— 不要这么做**，
在浅色画面上一眼就是贴上去的补丁，截图里非常明显。

**正确做法**：`grade.py` 的 `left_rolloff()`，只对最左 24%（向右羽化 9%）
做高光压缩，暗部与纹理保留。压完 11 个位置全部 ≥7.3:1，
左带亮度也回到参考站区间。章节大图**一律**要做；嵌板配图不在左栏底下，
用 `--no-left-rolloff` 关掉。

### 4.8 取样点可能落在所有表面之外

`surfaceAt(x,y)` 在章节之间、以及页面最末端嵌板收尾之后那一段会返回 `null`。
左栏页脚正好落在那里。早先版本此时干脆不设 `data-lt`，于是页脚退回默认的
浅色字、压在已经翻浅的 `body` 上，整块看不见。现在 `null` 时回落到
`body` 的 tone（那时候背后画的确实就是 body 底色）。
**新增跟随背景取色的元素时，一定要处理"背后什么都没有"这种情况。**

### 4.9 深底表面要整体重定义令牌，不要逐个补类名

加 `data-surface="accent"`（章节饱和色）时第一版是逐个补翻色规则：
`.muted` / `.en` / `.spec-v` / `.qa-a` …… 结果漏了 `.card-b`、`.compare .line`、
`.compare .why`，**AFTER 那一整栏字直接看不见**。

**正确做法**：在饱和表面的作用域里把 `--on-light` / `--on-light-muted` /
`--on-light-faint` / `--brass-ink` 整体重定义成深底版本，所有后代自动跟着翻，
以后加新组件也不会漏。反过来，自带浅色盒子的组件（`.compare .col`、`.qa-card`、
`.cloud-card`、`.reticle .r-lab`）要在盒子里把这几个令牌**还原**成浅底版本。
漏还原的代价：`.r-lab` 变成奶白字压奶白底，1.33:1。

### 4.10 `position:static` 会让 `z-index` 失效

窄屏与降级下把钉屏板改成 `position:static`，**`z-index:2` 随即失效**
（z-index 只对定位元素生效），背后 `position:sticky` 的章节大图（`z-index:0`）
反而盖到面板上面，整块底色连文字一起消失。

**用 `position:relative`**，不要用 `static`。

### 4.11 负的百分比 inset 会撑出横向滚动

`.over-art::before` 写成 `inset:-10% -6% -14% -14%`——左边探出是故意的（要盖住左栏小字），
但右边那 `-6%` 在 1114px 宽的容器上就是 67px，把 `documentElement.scrollWidth`
顶到 1451，全站多一条横向滚动条。**往右的负 inset 一律写 0。**

排查手法：别猜，写个同源 iframe 夹具遍历 `body *`，打印所有 `right > innerWidth`
的元素及其 `position` / `overflow`，一眼就能看出是谁。

## 5. 怎么验证（每批必跑）

### 截图：用本机 Chrome 无头模式，不要用 IDE 的浏览器预览

IDE 那个预览面板在本项目里**已验证不可靠**：会把 1384px 宽的页面渲染进一个
~170px 的角落，而且不派发 scroll 事件（探针实测触发 0 次）。

```bash
python3 -m http.server 4321        # 终端 1
cp tools/_shot.html .              # 夹具必须与 index.html 同源
tools/shoot.sh 1980 章节大标题       # 终端 2，输出到 .shots/
tools/shoot.sh 0 降级 1384 868 --reduced-motion
```

**已知坑**：`--virtual-time-budget` 会快进时间，CSS 过渡常被截在中途，
元素看着偏灰偏暗。判断"是不是真的没渲染"要去实时页面查 `getComputedStyle`，
**不要只信截图**（样板阶段为此白查过一轮）。

**A 批又踩到的两个截图坑**（夹具里都已修，别改回去）：

1. **`scroll-behavior:smooth` 会让截图停在半路的滚动位置。**
   站点 `html` 上有 `scroll-behavior:smooth`，`scrollTo()` 走的是动画；
   虚拟时间下这段动画常推不完，于是截出来的根本不是你要的那个 y。
   A 批一开始有一屏"内容整块消失"，查下去就是这个——元素其实没进视口。
   夹具里现在先 `documentElement.style.scrollBehavior='auto'` 再滚。
2. **iframe 移到屏幕外，它自己的 rAF 会被节流。**
   站点所有滚动逻辑都跑在 rAF 轮询里（见 4.1），iframe 一旦 `left:-9999px`，
   轮询就不跑，探针只能读到未初始化的状态。夹具把 iframe 留在视口内，
   报告用不透明浮层盖在上面（遮挡不影响 rAF）。

### 探针：读实时状态，不靠看图猜

```bash
cp tools/_probe.html .
tools/probe.sh 4600               # 输出 .shots/probe-4600.png
```

一次报出：横向溢出、`body`/顶栏/左栏各块的 `data-lt`、每块嵌板与画面的矩形和
背景色、撕纸毛边的填色、`.rise` 有没有该显形却没显形（**读类名，不受过渡时序影响**）、
每张图是否真的加载、嵌板内全部文字的对比度审计、控制台错误。

为什么不用 `--dump-dom`：它在主文档 `load` 事件时就把 DOM 吐出来，
那会儿 iframe 里的 rAF 还没跑完，永远只拿到 `PENDING`。所以报告画成可见文字走截图。

### 帧率要在真实时间里量

`--virtual-time-budget` 会快进时间，`performance.now()` 的间隔是合成的，
**headless 那条管道量不出真帧率**。走真实浏览器 + CDP：
先 `Emulation.setDeviceMetricsOverride` 把视口顶到 1384×868（否则会被渲染进一个小角落），
再用 `Runtime.evaluate` 跑一段 rAF 采样。A 批实测：中位 **59.9fps**、p90 54.9fps、
135 帧里 4 个长帧。

### 对比度

纯色底的文字用脚本扫（阈值 4.5:1，要求 0 缺陷）。
**压在图上的文字扫不出来** —— 脚本拿到的是区块背景色，不是图片像素。
那部分要用截图像素法：取文字区域上下的净空带，算 p90 亮度对前景的比值。

### 其它

- 帧率：连续 120 帧采样 `performance.now()` 间隔，中位 ≥50fps（当前 60fps）
- 响应式：375 / 768 / 1280 / 1440，`documentElement.scrollWidth` 不得超 `innerWidth`
- 首屏关键路径 ≤250KB（当前 160KB）
- 控制台无报错

### 4.12 夹层的 z-index 契约

参考站把巨型标题夹在画面的**背景层与前景层之间**（原生帧 `r014`：广告牌立柱从
Marketing 的字母中间穿过去）。两层平铺时再大的字也只是贴在图上，这是"不如参考站
吸引人"的头号原因。

层序必须是 **背景 1 → 标题 2 → 前景 3 → 嵌板 4**，且：

- `.chapter` 要 `position:relative; z-index:0` 建立层叠上下文，章内自洽
- `.chap-foreground` 用 **`height:0` 的 sticky**，内部再绝对定位撑出一屏。
  直接给它 100vh 会让每章凭空高出一屏
- **DOM 里必须排在 `.chap-backdrop` 之前** —— sticky 的起点是元素的静态位置，
  排在后面静态位置就变成 100vh，得多滚一屏道具才出现。绘制顺序由 z-index 定，
  与 DOM 顺序无关
- 前后景**必须共用同一个 `--art-scale`**（JS 挂在 `.chapter` 上，不是挂在
  `.art-wrap` 上），否则滚动时两层脱开

### 4.13 前景抠图的三个坑

**一、不要从成品章节大图里抠。** 明暗对照画整幅都暗（实测 `position.webp`
各区域暗于 40 的像素占比 75%–93%），亮度键分不开前景背景。
正确做法：`mmx image` 单独出"浅底、无投影的孤立道具"，再用 `tools/cutout.py`
阈值键出。深色道具 + 浅底 = 亮度差最大，抠得最干净。

**二、`<img width>` 属性会把道具横向拉扁。** 它是呈现提示，在没有任何 CSS 规则
设 `width` 时会生效，把宽钉死在属性值上，配 inline 的 `height` 就变形
（实测比例被拉到 3.006，原图 0.667）。`.fg-prop` 里**必须显式写 `width:auto`**。

**三、遮挡覆盖率要量字的墨迹，不能量元素盒。** `.chap-display` 是块级元素，
盒子撑满整列宽（x 270..1362），而字的墨迹只到 x=903。按元素盒算会得到虚假的 35%，
实际墨迹交叠是 **0%**——道具压根没碰到字。用 `Range.getBoundingClientRect()`
量墨迹：

```js
var rg = document.createRange();
rg.selectNodeContents(titleEl);
var ink = rg.getBoundingClientRect();   // 这才是字的真实范围
```

**红线**：只盖词尾或下半，绝不盖词首；盖掉 33%–40% 后仍要认得出是哪个词。
道具要 `filter:brightness(.42)` 压成前景剪影——参考站那根立柱是近黑的，
不压暗道具就会变成画面主体、跟标题抢主角。

### 4.14 遮挡量用「丢掉几个字母」判，不要用百分比

`tools/ink.sh` 报的墨迹覆盖率是好指标，但**它不等于可读性**。同样 33%：
落在长词（Interview，9 字母）上只吃掉尾巴，落在实心大件后面就能连吞三个字母。
第四章按 34% 定位时读成了「Intervi」，把 `right` 从 22.3% 推到 11.6%
（覆盖率降到约 16%）才读回「Interview」。

**判据**：只许划掉最后一到两个字母。覆盖率当参考，最终看截图认不认得出那个词。

### 4.15 抠图用「从画框泛洪」，不要用全局阈值

主体同时含极浅（纸张高光 ~200）和极深（轮廓 ~80）部分、又落在浅底（~247）上时，
全局阈值两头堵：调紧在浅色区打洞，调松把 AI 画的投影一起吃进来。两种失败都实测到了。

`cutout.py` 的 `build_alpha()` 改成从画框边缘泛洪求背景（半分辨率 BFS），
利用「主体轮廓一圈是暗的」这个事实——水进不到主体内部，浅色区自动保住；
投影与画框连通且比轮廓浅，会被一并淹掉。

配套两个参数：

- **`--inset`**（默认 0.02）：键出前先内缩裁边。出图常带**暗角**，
  那一圈暗于 gate 会把主体和画框连通，透明边距就裁不掉
  （实测 fg-essays 左右边缘各有 208/244 个像素暗于 gate，裁剪算出来是全画幅）。
- **`--thresh`** 现在是**泛洪的水位**，不是硬阈值。投影贴到画框那一段若暗于水位
  就成了一道坝，把投影内侧围成孤岛。fg-essays 那道坝实测 162–177，
  自动值 210 过不去，压到 **155** 才淹掉。
  放低水位不会漏进主体——主体内部被暗轮廓保护着，这正是泛洪优于阈值的地方。

**每张抠完必须放到洋红衬底上放大复核**，白边、残留投影、内部打洞一眼可见。

### 4.16 拼贴构造：明亮背景的章节，巨型标题必须翻成深墨

用户指出抠图"突兀"，回看原生帧 `/tmp/refnat/intro02.jpg` 确认了参考站的真实构造：
**背景层是简单干净的风景画，人物与物件是单独抠出来的前景层**——是拼贴，不是一幅画。
问题不在用抠图，在四个做法上：

| | 参考站 | 之前做的 |
|---|---|---|
| 背景 | 明亮简单，中段特意留空给标题 | 近黑暗室（平均亮度 18–30） |
| 抠图尺寸 | 人物占屏高约四成 | 道具中等，缩在角落 |
| 抠图明度 | 全亮度高饱和 | `brightness(.42)`，成了脏污一团 |
| 点睛色 | 品红统一现代物件 | 无 |

**踩到的坑：我给自己写的验收指标自相矛盾。** 原定「背景平均亮度 ≥70」+
「标题带 p90 ≤90」——整体要亮、字底要暗，同一张图上做不到。
实测提亮后标题带 p90 = **229**，奶白标题压上去只有 1.1:1。

**正确做法不是加重暗床**（那等于把刚提亮的背景压回去，提亮白做），
而是**把巨型标题翻成深墨**：`.chapter[data-hero="light"]` 里重定义 `--display:#12161F`，
暗床换成极淡的提亮层。实测对比度 **15.25:1**。
背景块同时标 `data-tone="light"`，左栏与顶栏靠已有的 `surfaceAt`/`data-lt` 机制
自动翻成深色墨，一行额外代码都不用写。

配套两条：

- **明亮背景不要做 `left_rolloff`**。那是给"浅色小字压暗底"设计的；左栏翻成深墨后
  它既没必要，又在 24% 处留下一道可见竖直接缝。用 `--no-left-rolloff`。
- **左侧 140–270px 放不下人物**。左栏目录占 x 14–140，标题从 270 起，
  中间只有 130px。硬塞左侧人物必然压住目录或撞上标题起点（两条红线）。
  双人构图要把两人都放在右半边（前后错开），左侧留给风景。

**`tools/ink.sh` 的已知局限**：每章只量第一个 `.fg-prop`。多件前景时它的读数
不代表真正压住标题的那一件，要以截图为准。

### 4.17 拼贴的元素配额，与两个位置红线

参考站开场一屏有 **5 个抠图元素**（两人物 + 咖啡杯 + 滑板 + 购物袋）。
只放两个人物会显得空——"丰富"是可量化的。现在每章 **4 件**：
2 个人物 + 2 件**悬浮**黄铜物件（悬空而不是落地，拼贴意图才明确）。
三件通用物件（卷宗 / 行李箱 / 奖牌眼镜）跨章复用，只改位置尺寸旋转。

两条位置红线，都是实际撞到才知道的：

1. **体量大的人物会把后面的元素整个盖住。** 第四章学者 88vh 放在 `right:0`，
   把 `right:34%` 的学生和 `right:24%` 的奖牌全遮了——DOM 里学者在最后，画在最上层。
   多件前景要按「从远到近」排 DOM，并留足横向间距。
2. **人物不能压到正文。** 学生挪到 `right:49%` 后压住了中文导语的行尾。
   前景可以压标题（只许划掉最后一到两个字母），**但绝不能压正文**。

### 4.18 出图脚本必须校验文件真的落盘

`gen5.sh` 里的 `g()` 在 `mmx` 调用后**无条件**打印 `✓ $1`。
`fg-student-answer` 那次生成实际失败了，日志却报成功，
下游 `[[ -f ... ]]` 静默跳过抠图，直到截图里发现少了一个人才查出来。
**批量出图的成功标记一律要 `test -f` 之后再打。**

### 4.19 横滚幕间用钉屏映射，不要用 overflow-x

真横向滚动会和手机返回手势、触控板横扫打架，而且没法跟纵向节奏对齐。
做法是 `position:sticky` 钉住一屏 + 内层 `transform:translateX`，
**章高由 JS 设成 `100vh + 内容溢出宽`**，纵向滚动量与横向行程一一对应
（实测滚到底 `--hx` 与溢出宽差 <1px）。窗口尺寸变了要重跑 `layoutH()`。

配套两条必须有：

- **进度条**。被钉住而没有长度提示，用户会以为页面卡死。
- **窄屏与降级整段拆掉**。`<1024px` 与 `prefers-reduced-motion` 下
  取消钉屏、拆成纵向堆叠（星野长卷则整段 `display:none`，
  靠结果章里那份完整案例清单承载信息）。

### 4.20 进度驱动的"依次点亮"要按屏上位置判，不要按内容坐标推算

星野第一版用长卷坐标算点亮阈值（`p * 长卷宽`），结果开头有一段
视口里已经有星、却还没到阈值，第一屏是空的。
改成量星点的 `getBoundingClientRect().left` 与视口边缘比，一次就对了。
**已点亮的从待办表移除**，所以每帧只量还没亮的那几颗，全亮之后开销归零。

### 4.21 鼠标跟随要单独一条便宜通道

跟滚动那条全套共用的话，指针一动就会对全部抠图各做一次
`getBoundingClientRect`——26 件就是每帧 26 次强制布局，
而它真正需要更新的只有两个 CSS 变量。
拆开后：滚动时跑全套并缓存可见性，指针移动只写 `--mx/--my`。

## v6.1 图版流水线（`tools/plate.py`）

把照片转成「印在这份文件里的图版」而不是「贴在上面的照片」。
这个区别是 v6 能不能加图的前提——v6 把 38 张图全删掉，
就是因为它们以照片的身份出现、与 `Quiet technology` 打架。
半色调网屏解决这件事：**网点本身就是印刷品的证据**。

### 已验证可用的参数

```bash
python3 tools/plate.py art-src/pl-x.jpg 名字 --cell 5 --out-width 900 --colors 6 --contact
```

- **输出宽度是体积的主要杠杆，不是网格密度。** 实测同一张图
  cell=4/6/8 在 1280px 下都是 136–143KB（网点的高频信息 PNG 压不动）；
  降到 900px 立刻掉到 42KB。正文栏最宽约 880px，给 1280 是浪费。
- **必须导出 PNG，不能用有损 WebP。** 网点边缘一糊，图版就退回成照片。
- 量化到 6 色即可，三种墨之间的过渡不需要 24 位。

### 两个踩过的坑

**一、`autocontrast` 会毁掉高调源图。** 这批物证照片是高调的
（实测 p5=170 / 中位 184 / p95=240，整张挤在亮部三分之一）。
`autocontrast(cutoff=1)` 把 170 拉到 16，浅灰台面直接变成近黑实地。
改成按每张图的 p2–p98 映射到 30–232（`press_lut()`），不铺满 0–255，留住纸的呼吸。

**二、目前最大的障碍在源图，不在流水线。**
半色调靠灰度驱动点的大小，源图必须有**连续的中间调**。
但 MiniMax 对"俯拍平铺静物"有很强的先验，产出的是**两个平调**
（白纸 + 灰底，中间几乎没有过渡）。
第一版提示写了"均匀柔光无硬阴影"——那是我的错，方向正相反；
但第二版改成"侧逆光、深阴影、连续影调、可见纹理"之后，
重出的 `pl-transcript` 影调签名与第一版**完全一致**（p5=170 / 中位 184），
提示没能压过模型先验。

**下次继续做这件事的人**：不要再在提示上反复试。可行的方向是
（a）换题材——有明确立体结构的实物（仪器、书脊、折叠纸张）比平铺纸张容易出影调；
（b）在流水线里用局部对比增强人为造出中间调再打网点；
（c）改用矢量图版，与现有「图 1–3」同一套线条语言。
