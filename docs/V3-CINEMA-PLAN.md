# 引力坊官网 v3 — 电影级体验完整方案

> **性质：** 规划文档，不是画饼。依据 Oryzo AI 全站录屏（`录屏2026-07-29 04.18.36.mov`，约 119s）拆解 + 第一性原理约束。  
> **目标：** 在 **可交付、可维护、可换摄影** 的前提下，逼近 Oryzo 的「流程与呈现语法」，而不是复刻 Lusion 工作室产能。  
> **已确认偏好：** 实时 WebGL；主角为简单高级 **Halo 圆环**；背景摄影后续替换。  
> **帧备份：** `docs/ref-oryzo-v2-frames/f00–f21.jpg`（分析用）。

## 0. 第一性原理：Oryzo 到底赢在哪

### 0.1 它不是「好看的网页」

录屏里的 Oryzo 是：

| 层 | 本质 |
|----|------|
| 主媒体 | **连续视觉电影**（3D 场景 / 棚拍级产品 / 影廊 / 材质微距 / 特效世界观） |
| UI | **字幕轨 + 导航壳**（字少、奶油色、固定位置规则） |
| 滚动 | **剪辑时间轴**（不是 section 堆叠） |
| 主角 | **同一物理物件**贯穿全片（杯垫） |
| 节奏 | 一幕一论点，大量「只看图不说话」的纯视觉段 |

### 0.2 录屏全流程（按时间顺序）

| # | 大致时段 | 幕 | 画面语法 | 文字角色 |
|---|----------|----|----------|----------|
| 1 | 0–6s | **Hero 场景** | 写实桌面世界：切割垫、笔、刀、杯垫居中 | 超大 ORYZO + 短句 + 角标卡 + PLAY |
| 2 | 6–12s | **物件特写** | 黑棚、杯垫填满画面、强材质 | 左右对仗大标题 + 短说明 |
| 3 | 12–20s | **手持 / AI 宣言** | 手 + 物件 + 大标题 Powered by AI* | 标题主导，物件居中 |
| 4 | 20–28s | **影廊** | 中心画框 + 左右模糊幻灯 + 虚线取景框 | 一句「So portable…」 |
| 5 | 28–40s | **回到使用场景** | 桌面咖啡杯；切热成像世界观 | 功能说明 + 滑杆 UI |
| 6 | 40–50s | **工程草图** | 暗底、红线稿、贝塞尔控制点 | 左文案 + 右公式/标注 |
| 7 | 50–58s | **桌面互动** | 完整 3D 工位 + 中心交互按钮 | 大标题 SMART FLIP… |
| 8 | 58–65s | **材质微距** | 灰阶纹理全屏 + 小信息卡 | 中心标题 + 指标卡 |
| 9 | 65–72s | **材质转场** | 全屏树皮/软木截面展开 | 几乎无字，纯视觉 |
| 10 | 72–80s | **可持续浅色块** | 插画卡片网格（浅色中断） | 说明文 |
| 11 | 80–88s | **评价 + 物件** | 大标题 + 杯垫特写 | 社证 |
| 12 | 88–100s | **生活方式横滑** | 三栏电影海报级摄影 | 大字压图 |
| 13 | 100–108s | **选配** | 黑底 + 大 ORYZO + 三档 pill + 物件 | 规格文案 |
| 14 | 108–119s | **收尾** | 咖啡豆粒子场 + 大 CTA 文案 + 表单 | 招揽转化 |

**贯穿 UI 常量：** 左上 Logo · 右上 INTRO/FEATURES/PRODUCT/CONTACT · 底中 SCROLL TO CONTINUE · 右侧细进度轨 · 奶油字 · 暖黑底 · 橙强调（品牌色）。

### 0.3 可复制语法 vs 不可复制产能

| 可复制（流程/语法） | 不可复制（除非加预算/周期） |
|--------------------|---------------------------|
| 导航壳 + 滚动提示 + 进度轨 | 整桌道具实时 3D 场景 |
| 「一幕一世界」的分幕结构 | 热成像整间房实时着色 |
| 奶油大字 + 极少正文 | 手绘 WebGL 贝塞尔草图交互 |
| 主角物件串场（Halo） | 软木树皮全屏体积感转场 |
| 影廊 / 横滑海报墙（用摄影） | 咖啡豆实时物理粒子（可做弱化版） |
| 功能幕 = 图 + 短文 + 一个控件 | 10+ 定制时尚大片制作 |
| 选配三档 / 规格列表 | 与 Lusion 同等的光影调色管线 |
| 摄影底图可替换插槽 | 单人两天「做出一模一样」 |

**结论：**  
Oryzo 的「高级」= **美术资产密度 × 剪辑精度 × 物件真实感**。  
我们没有 Lusion 团队时，正确策略是：

1. **用摄影/预渲染补「世界」**（你说后面会换真摄影 —— 这是正确路径）  
2. **用实时 WebGL 只做 Halo**（简单、可控、可高级）  
3. **用滚动剪辑语法** 把摄影 + Halo + 字排成电影  
4. **砍掉** 无法一次做真的互动 3D 小游戏式功能幕，改为 **「可感知的轻交互 + 强视觉」**

## 2. 主题系统（Theme）

### 2.1 物理场景句（决定明暗）

> 访客像在 **暗房看一部 8–10 分钟的品牌短片**：暖黑影院、奶油字幕、一枚安静发光的金属/玻璃 **Halo** 始终在场；偶尔切入真实摄影世界（办公室、路径、人群、录取时刻），再回到暗棚特写。

→ **主舞台：暖黑影院**，不是浅色咨询所，也不是纯赛博蓝。

### 2.2 色板（固定，少即是多）

| Token | 方向 | 用途 |
|-------|------|------|
| Stage | 暖黑 `oklch(0.12–0.14, 低 chroma, hue~50–60)` | 全站底 |
| Cream | 暖米白 `oklch(0.92–0.94, 微 chroma)` | 标题与主 UI 字（对标 Oryzo 奶油字，**禁止纯 #fff**） |
| Cream/50–60% | 同上降透明 | 正文 |
| Teal | 沉稳青绿 `oklch(~0.62–0.68, 0.09–0.11, hue~185)` | **唯一强调色** ≤10%：CTA、active nav、Halo rim、进度 |
| Line | cream 10–18% | 虚线框、分割 |
| Film panel | stage 半透明 + blur | 信息卡（少用） |

**不做：** Oryzo 橙（那是别人品牌）、Swiss 红蓝、亮霓虹、浅灰 SaaS 默认。

### 2.3 字体

| 角色 | 选择 | 规则 |
|------|------|------|
| Display 西文 | Sora（已用）或更冷一点的几何无衬线 | 超大标题 tracking 紧、字重 600 |
| 中文/正文 | Noto Sans SC | 正文 15–17px，行高 1.55–1.65，measure ≤42–55ch |
| UI 小标 | 同族 10–11px，uppercase + tracking 0.16–0.22em | 导航、SCROLL、标签 |

**禁：** Inter / Space Grotesk 作新默认；渐变字；全大写长正文。

### 2.4 间距与网格

- 内容宽：约 1120–1200px  
- 左右 gutter：`clamp(1.25rem, 4vw, 2.75rem)`  
- **一幕默认 100svh**（可 120–160svh 若需 pin 滚动 scrub）  
- 字与 Halo：**故意不对齐死板居中** —— Hero 字偏左，Halo 偏右/中（对标 Oryzo 产品偏画面重心）  
- 虚线取景框：仅用于「影廊焦点框」「指标卡」，不滥用

### 2.5 动效原则

| 允许 | 禁止（第一性） |
|------|----------------|
| Lenis 平滑滚动 | 为炫技的无限 loading 秀 >3s |
| Scroll progress → Halo 位姿/相机 FOV | 同时动 10 个 DOM 属性 |
| 章节文字 mask / fade-up（短） | 弹跳、elastic |
| 影廊横向 scrub 或 snap | 自动无限跑马灯（廉价感） |
| `prefers-reduced-motion` 降级 | 无障碍上「动效强制」 |
| Bloom 轻微 + Vignette | 全屏糊玻璃拟态 |

缓动统一：`cubic-bezier(0.16, 1, 0.3, 1)` 或 expo.out。

## 3. Halo（实时 WebGL）—— 做什么 / 不做什么

### 3.1 形态（你已定：简单圆环）

- **外环：** 细 torus，物理金属（高 metalness、中低 roughness、环境反射）  
- **内环：** 更细，Teal rim / 微 emissive  
- **可选极细引导环：** opacity ~0.1  
- **不要：** 卫星、节点球、icosahedron、数据粒子喷泉、复杂 morph 成「树」

### 3.2 串场行为（可实现的关键帧）

| 进度段 | Halo | 相机 |
|--------|------|------|
| Intro | 偏右，中等大小，缓转 | 稍近，俯仰轻 |
| 宣言 / 特写 | 居中放大 | 更近，像产品棚 |
| 方法 | 侧倾 + 双环轻微略增 | 稍远 |
| 系统 | 略收，rim 更亮（科技感） | 略俯视 |
| 案例影廊 | 移到一侧或缩小让位给摄影 | 让出中心 |
| 团队/声音 | 安静小，边缘 | 退 |
| 联系 | 正对、稳定「印记感」 | 中距静止 |

实现：滚动 0–1 采样关键帧（已有 `lib/scroll-story.ts`）+ `useFrame` lerp。  
**这做得到。**

> **必改（架构）：** 现 `HALO_KEYFRAMES` 把 `p` 硬编码成全局进度（`0 / 0.16 / 0.34 …`）。这样一砍幕或一加幕，所有 `p` 都要重算手调 —— 正是 Act 6/9 分期的隐性成本。**关键帧改为绑定幕 id，`p` 由幕表在运行时推导**，则 V3-A→V3-B 加回 Act 6/9 只是加数据，不是重调整条曲线。

### 3.3 做不到却常被期待的

- Halo「变成真实软木/真实金属摄影级」仅靠程序 torus：做不到 Oryzo 杯垫的微观材质。  
- **补救：** 摄影章用真图；Halo 章用灯光与构图的「贵」，不靠假纹理糊弄。  
- 若未来有 glTF 高精度环模型，可替换几何，接口预留 `Halo` 组件单一入口。

### 3.4 性能边界

- 桌面：DPR ≤1.75，Bloom 开  
- 移动：DPR ≤1.25，Bloom 关，阴影简化或关  
- 单 Canvas 全站固定一层 `pointer-events: none`  
- 禁止每章新建 Canvas

## 4. 背景（摄影 / 世界）—— 可替换资产表

> 原则：**世界靠摄影，物件靠 WebGL Halo。**  
> 目录：`web/public/scenes/`（可扩展 `gallery/`）。

### 4.1 必须有的幕背景（上线最低集）

| 文件 | 对应幕 | 拍摄/画面建议（给摄影师的 brief） | 无图时临时 |
|------|--------|-----------------------------------|------------|
| `intro.jpg` | Hero | 安静工作台/书桌/窗光，偏暖，**中央或偏右留空给 Halo 合成感** | 暖黑径向渐变 |
| `method.jpg` | 方法 | 抽象路径、地图、书架、走廊纵深 | 暖暗渐变 |
| `systems.jpg` | 系统 | 屏幕光、深色界面环境（可虚化） | 冷青绿暗渐变 |
| `cases-01…04.jpg` | 案例影廊 | 4 张「结果时刻」氛围图（校园、城市、书桌、证书虚化等）**勿假冒校徽侵权** | 纯色卡 + 校名排版 |
| `contact.jpg` | 联系 | 极简暗调静物/城市夜景虚化 | 深黑 |

### 4.2 强烈建议（第二批，质感跃迁）

| 文件 | 幕 | 说明 |
|------|----|------|
| `hero-detail.jpg` | 物件特写幕 | 暗棚产品摄影（可与 Halo 二选一：有图则压低 3D 存在感） |
| `gallery-01…06.jpg` | 生活方式/信任横滑 | 对标 Oryzo 三栏海报墙 |
| `macro.jpg` | 材质/精密幕 | 金属拉丝/纸张纤维微距（表达「精密」） |
| `team` 已有人像 | 团队 | 继续用现图，建议后期统一调色到奶油-暖黑 |

### 4.2b 摄影 brief 硬约束（给摄影师，缺一项即返工）

| 项 | 要求 | 原因 |
|----|------|------|
| **横竖两版** | 每个场景各拍 16:9 与 9:16 两版（或横版把主体压在中央 40% 安全区内） | 一幕默认 100svh，手机上是约 9:19 竖屏，横 16:9 图会被裁掉大半宽度 —— intro 说好的「右侧留空给 Halo」在手机上直接失效 |
| **暗部曝光余量** | 不要拍死黑；后期要整体压暗并叠奶油字 | 压暗已经很暗的图会出现色阶断裂 |
| **留白侧固定** | intro：主体压左，中央到右侧留空（Halo 合成位） | 与 §3.2 Halo 关键帧位姿绑定 |
| **色温** | 偏暖，避免冷白荧光 | 全站 stage 是暖黑，冷图混进来会脏 |
| **交付** | 长边 ≥3000px，RAW + JPG | 站上用 WebP ≤350KB，需要下采样余量 |

> 因为要横竖两版，§10 的「最小 11 张」实际是 **15–16 次构图**，排期按此算。

### 4.3 技术约定

- 格式：JPG/WebP，长边 ≥1920，单图 ≤350KB  
- 命名稳定，代码只认路径  
- `SceneStage`：有图用图，404 自动 fallback（已实现于 `components/ui/SceneStage.tsx`）  
- **首屏例外：** 当前 `SceneStage` 用 `new Image()` 探测成功后才挂 background，首屏图无法被 preload，LCP 会掉且有一次可见的 fallback→照片跳变。**intro 必须改用 `next/image` + `priority`**；JS 探测只保留给非首屏幕  
- **版权：** 只用自有摄影或已购授权；案例勿用未授权名校官方视觉

## 5. 文字系统（呈现规则）

### 5.1 字阶（Display 电影字）

| 级 | 用途 | 约值 |
|----|------|------|
| H0 | 品牌一词 / 幕标题 | `clamp(3.5rem, 10vw, 7.5rem)` |
| H1 | 幕主张 | `clamp(2.2rem, 5vw, 3.75rem)` |
| H2 | 卡片/阶段 | 1.25–1.5rem |
| Body | 说明 | 0.95–1.05rem，cream/55 |
| Label | 导航/SCROLL | 0.65–0.7rem，tracking 宽 |

### 5.2 文案密度（对标 Oryzo：少）

- **每幕主标题 ≤ 1 行（中文可 2 行）**  
- **副文 ≤ 40–60 字中文 / 2–3 句英文**  
- 方法阶段：标题 2 字级 + 一行解释  
- 禁止段落堆砌；长内容放弹层/二级

### 5.3 中英

- `content.ts` 每键 `{ zh, en }` + `experience-store` 的 `t(dict)`（已实现，比「字典」方案更省心）  
- 中文默认；切换不重载  
- 英文是否需要独立 URL 见 §13.1-C  
- 产品名：Terra / Life-echo 可保留英文专名 + 中文解释

### 5.4 关键文案骨架（可写进 content.ts，仍可改）

| 幕 | 中文主张（草案） | 英文主张（草案） |
|----|------------------|------------------|
| Hero | 名校路径，精确规划。 | Elite paths. Precision planning. |
| 再定义 | 不只是中介。 | Not just an agency. |
| 方法 | 一条路径，拆到可执行。 | One path, broken into steps. |
| 系统 | Terra 总台，三端环绕。 | Terra at the core. Three satellites. |
| 案例 | 结果说话。 | Results speak. |
| 团队 | 专业，可核对。 | Expertise you can verify. |
| 联系 | 开始对话。 | Start a conversation. |
