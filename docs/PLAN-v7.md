## P0 · 已修并验证（记录在此，供复核）

写这份计划时验出两个上线阻塞项——**v6 重写之后从未在窄屏验过**——现已修掉。

### 1. 375px 横向溢出 → 已修

`scrollWidth` 曾是 391 对 375。**第一次诊断错了**：我以为源头是 §5 的记录表，
给它加了 `min-width` 反而把越界推到 580。

实际上 `.scroller` 一直工作正常（实测 w=335 / scrollWidth=560 / clientWidth=335），
真正越界的是 **§3 §4 §6 §7 那四张裸 `<table>`**——它们在 `.tbl` 里没有滚动容器，
`min-content` 直接把 `documentElement` 顶开。约束加在 `.tbl` 上即可。

> **排查手法**：别按"哪个元素最宽"下判断。要过滤掉**已在滚动容器内**的元素
> （逐级向上查 `overflowX` 是否为 `auto/scroll`），剩下的才是真凶。
> 我漏了这一步，第一次就修错了对象。

### 2. 触摸目标不足 → 已修

筛选按钮 32px → 44px，表单控件与提交键一并抬到 44px，
`@media (pointer:coarse)` 下再撑目录与顶栏的点击区。
句中内联链接按 WCAG 2.5.5 的内联豁免不计。

**复核结果**：375 / 768 / 1280 三档 `scrollWidth` 与 `innerWidth` 相等，
容器外越界 0，表单与按钮无一低于 44px。

### 3. 三项补验 → 已跑完（4241f9e 上又复跑一轮，含真实帧率）

接手时按"别假设没问题"复跑，仪器是新的 **`tools/cdp.mjs`**（真实 Chrome + CDP，
Node ≥22 自带 WebSocket，**不需要再装 websocket-client**）：

**`prefers-reduced-motion`**：6 条规线全部直接画完（其中 3 张图尚未进视口，
证明是 CSS 覆盖而非 `.in` 兜底）。可见文字元素 **392 = 392**（两态一致；
比上一轮的 374 多，是因为刊头图版零在此之后才进页面）。
不可见元素两态都是 5 个：4 个 `<option>` + 内联 `<script>`，属正常。
**降级不吞任何内容**。

**§5 筛选组合**：9 个组合（单 / 双 / 三条件）显示行数、期望行数、计数器
**三者全部一致**，`aria-pressed` 状态逐组核对无误；空分支（本科+欧陆+工程）
显示 0 不崩，重置回 21。**复跑抓到一个真缺陷**：Cambridge（Chemistry）的
`data-d="SCI"` 没有任何筛选按钮可达——「工程与理」字面上含理科，该行却在该
筛选下消失。已修为 `data-d="ENG"`，修后 `d=ENG` 由 9 行变 10 行。

**真实帧率**：这次是真帧间隔，不是 handler 耗时推算。真实 Chrome（非虚拟时间）
+ `Emulation.setDeviceMetricsOverride` 1384×868 + 滚动中连续 239 帧 rAF 采样：
中位 **16.7ms（59.9fps）**、p90 17.4ms（57.5fps）、>34ms 与 >50ms 长帧 **均为 0**。
（`3b641fa` 记录的是 handler 耗时：中位 0.000ms、p95 0.100ms——两个口径都安全。）

回归顺带补齐：对比度 **411 处零缺陷**；375/768/1280/1440 四档 `scrollWidth`
均不越界；5 张图全部加载；控制台无错误。一条命令：`node tools/cdp.mjs all`。

## P3 · 内容深化

按价值排序，不必全做：

### 0. 图版范式修正（业主两轮指示 2026-08-04，已落地）

**第一轮**：业主看刊头打样——「不够直观、太有故事感」。
试做标本化样张（单件信封 + 注记层），**被否**：
米白信封压浅灰纸面，主体与底都是高调，双色调映射把两者并成同一档黄铜，
网点打出来分不清形——「现在都看不清东西了」。

**业主定调**：章节图版**保持场景版**，但标准提高——要更具体、
真实东西的感觉：纸的质感、各物体的特点必须看得见，色层要分得开。
刊头图版单独走单件标本（业主自选）：单件横幅 + 注记排在净空处。

**落地**：

- 图版一 / 二 / 三：维持场景版不动（`pl-envelopes` 等三张业主认可）
- 图版零：`pl-desk`（桌面场景）→ `pl-passport`（深红封皮护照单件横幅，
  900×352 · 26KB · 源图跨度 169）。深物压亮底，物体一眼可辨；
  左侧净空排注记 ① 烫金压印 ② 封皮纹理 ③ 侧光深影，图注写规格句
- 注记层（`.plate-note`）只服务刊头；窄屏 `<640px` 整层隐藏，
  特征清单在图注里，不丢内容；打印随图版一起印
- 新判据：**跨度够 ≠ 分得清**。选源图除了跨度 >110，还要主体色层与
  底色层分开（深物压亮底或反过来）——pl-letter 跨度 208 仍翻车，已记进
  `HANDOFF.md` 图版流水线一节的坑三

1. **更多图版**：§2 §3 §4 §6 §8 目前无图版。题材继续走"申请季的物证"，
   但注意别让图版多到打断阅读——年刊里图版是稀缺件。
2. **图 2 用真实分布驱动**：现在的概率梯度是示意柱，柱高是手写的。
   若有真实的档位分布数据，让柱高由数据生成，图注写明口径。
3. **边注承载交叉引用**：现在每节只有一条限定条件，可以加"参见 §4 表 2"一类的互引。
4. **中文标题字**：目前中文全走系统字体栈。若要更强的识别度，
   可子集化一款开源中文字体**只用于标题**——但中文 webfont 动辄 5MB+，
   必须子集化到只含用到的字，否则国内加载会毁掉首屏。

## P4 · 上线前的最后一件事

**表单没有后端。** `index.html` 里搜 `FORM_ENDPOINT`，现在是空字符串。
空的时候行为是诚实的：不发请求、不给"提交成功"的假象，
而是把信息复制到剪贴板并把二维码顶到眼前。

要真正收到线索，**需要业主自己注册第三方表单服务并提供端点**——
这一步不该由开发者代办（涉及注册账号与凭据）。
